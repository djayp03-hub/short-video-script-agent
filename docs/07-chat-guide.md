# 聊天页面使用说明

## 在 PyCharm 中点击运行

1. 打开项目根目录的 **run_chat.py**，右键，选择「运行 run_chat」。使用你现有的 Python 3.10+ 解释器，不需要安装新依赖。
2. 脚本参数留空。程序会打开浏览器，地址为 **http://127.0.0.1:8765/**。没有自动打开时，将这个地址复制到浏览器。
3. 默认选择「离线演示」，不需要密钥。点击示例填入需求，再点击发送。
4. 如果运行窗口一直没有退出，这是正常的：网页服务需要持续运行。停止 PyCharm 运行会关闭服务。

如果要手工配置：脚本路径选 `<项目根目录>/run_chat.py`，工作目录选项目根目录，参数留空。默认资料与 `.env` 的位置从脚本所在项目定位，不依赖 IDE 当前工作目录。

`run.py` 仍是原来的单次生成入口。**聊天请运行 run_chat.py。**

## 可以怎样交流

先输入：

> 我想介绍剪映盒演示版的字幕功能，30秒。

程序会追问缺失的受众、平台和风格，再回复：

```text
受众：学生
平台：抖音
风格：清晰自然
```

生成后继续输入：

> 缩短到15秒

同一会话会保留已知需求，并带入同主题、同产品的上一版草稿。程序先测量基线，再提交有变化的新稿并重新检查。不能把没有修改的原稿当成已完成修改。换主题或产品时重新生成，不沿用旧稿。

右侧显示需求、标题、分镜、预计时长、来源 ID、风险和检查状态。展开素材来源与执行记录可逐项核对。可以下载 Markdown 脚本和 JSON 结果。

仅交流而没有运行工具时，不会产生本轮完成状态。如果需求未变化，可继续显示带有「上次脚本」说明的参考结果。

## 自由交流与真实模型

离线模式是固定规则模拟器，支持示例中的补参、明确字段和时长缩短，不代表自然语言理解或真实创作效果。无法理解的要求会提示切换真实模式；无法完成的风格改写明确返回未完成。

要自由表达、解释脚本、调整风格或改写文案：

1. 在项目根目录 `.env` 填好百炼配置。可以复制 `.env.example`，已有文件请直接编辑。
2. 填写自己的 `VIDEO_API_KEY` 或 `DASHSCOPE_API_KEY`，默认模型 `qwen-plus`，中国内地兼容地址为 `https://dashscope.aliyuncs.com/compatible-mode/v1`。
3. 停止并重新运行 `run_chat.py`，刷新页面，在右上角选择「真实模型 · 百炼」。切换模式会新建会话。
4. 发送消息后，模型整理本轮需求；需要生成时，继续执行原来的模型与工具循环。

密钥从服务器本地配置读取，不发送到网页。真实模式的用户消息与选定资料会发送到配置的模型服务，并产生调用费用。真实失败不会自动切换成离线模式。

开发验证时未使用可用密钥，因此**已验证离线页面与真实模式缺密钥处理，尚未完成新聊天功能的真实模型效果评测**。之后已确认本地配置了百炼密钥；配置成功不等于效果评测通过。此前 CLI 的真实记录仍是历史版本证据。

## 补充素材

展开输入框上方「补充产品素材」，填写产品名和可引用的资料正文，再发送一条消息，例如「我补充了资料，请继续生成」。

资料加入当前会话，获得 `U-…` 来源 ID，并随每次生成保存快照。产品名应与需求中的产品一致。每会话最多20条，正文每条最多8000字；超长资料请分次添加，整个 HTTP 请求最多64 KiB。

补充资料是用户提供的事实来源，不代表程序已独立核实其真实性。它不修改项目的原始 data/materials.json。

## 会话与文件

刷新页面会恢复当前会话。在相同浏览器、相同端口重新打开服务，也可恢复最后一个会话。切换端口属于不同网页来源，浏览器不会自动带上旧会话编号。

点「新建对话」开始独立任务，清空输入和素材编辑框。旧记录仍在磁盘中保留，当前页面暂不提供历史会话列表。

```text
runs/chat/<会话ID>/
  state.json              # 会话消息、结构化需求、最近结果、补充资料
  turn-0001/
    dialogue.json         # 本轮用户消息、对话规划、回复及整理需求的模型调用
  turn-0002/
    dialogue.json
    input.json            # 如果本轮执行 Agent，另有以下文件
    output.json
    trace.jsonl
    model-calls.json
    revisions.json
    materials.json
    rules.json
    run.json
    script.md             # 本轮有稿件时
```

`model-calls.json` 记录脚本 Agent 的调用；`dialogue.json` 中的 `chat_model_calls` 单独记录需求整理调用。`initial_draft_kind=conversation_previous_draft` 表示上一轮稿件，不是人为提供的错误初稿夹具。

运行中停止服务后，下一次恢复会话会把未结束的请求标记为 `incomplete/interrupted`，保留原记录，不能假称生成完成。

## 常见问题

| 情况 | 处理 |
|---|---|
| 地址打不开 | 保持 PyCharm 中 run_chat.py 正在运行，检查运行窗口打印的地址 |
| 8765 已占用 | 停止先前服务，或在脚本参数填 `--port 8766` 后打开新地址 |
| 不想自动打开浏览器 | 参数填 `--no-browser` |
| 希望默认真实模式 | 配好密钥后参数填 `--mode real` |
| 提示缺密钥或401 | 检查本地 `.env`、环境变量优先级和服务地域，重启服务；不要把密钥粘贴到聊天框 |
| 等待较久 | 每次真实生成可能包含多次模型调用，页面会显示处理中，请等待本轮结束 |
| 想改变风格但离线未完成 | 离线不实现自由创作，请切换真实模式 |

每会话最多40轮，每条消息最多4000字。同一会话同时只能执行一条消息。真实每轮最多1次需求整理调用，加上 Agent 最多24次调用；Agent 默认12步、240秒，需求整理请求单独最多35秒。网页仅绑定本机地址，不提供互联网部署、多用户账户或生产级服务。
