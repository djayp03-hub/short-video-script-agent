# 短视频脚本 Agent：运行说明书

现在有两个入口：**run_chat.py 打开聊天页面，run.py 执行一次脚本生成**。如果想直接与项目交流，在 PyCharm 打开根目录 run_chat.py，右键运行，参数留空。浏览器将打开本地工作台。详细补参、连续改稿和真实模式步骤见 [聊天页面使用说明](07-chat-guide.md)。

下文保留原有单次生成与本机快捷配置说明。

## 在当前 Codex 中点击运行

项目已配置 `.codex/environments/environment.toml`，包含三个 Actions：

| 按钮 | 做什么 | 前提 |
|---|---|---|
| Run | 离线运行默认样例，自动创建 runs/mock-时间戳 | 无需密钥或联网 |
| 真实生成 | 用真实模型生成脚本，自动创建 runs/real-时间戳 | 在根目录 .env 填好 VIDEO_API_KEY |
| 运行测试 | 执行 unittest 工程测试 | 无需密钥或联网 |

在 Codex 模式下打开当前项目，使用顶部项目操作菜单中的上述动作。若当前窗口尚未显示它们，重新打开该项目，并在本地环境设置中检查或选择“短视频脚本 Agent”。官方文档说明 Actions 会显示在顶部并在应用的集成终端执行；这不是要求你每次输入命令。

先点击 Run，完成后在左侧文件树打开最新的 runs/mock-时间戳/script.md 和 output.json。修改 data/request.json 后再点按钮即可；程序会自动生成新的结果目录。

配置中的命令已在当前电脑验证：Run 成功，40 项测试通过。尚未通过实际界面点击确认按钮是否已被当前窗口加载；真实生成也没有在配置期间调用。按钮命令使用当前已验证的 Python 路径，更换电脑或解释器后需要更新该路径。此配置只提供启动与测试快捷入口，不代表完整的断点/变量监视调试器。

参考：[官方本地环境与 Actions 文档](https://learn.chatgpt.com/docs/environments/local-environment)。

本项目输出可编辑的短视频脚本。当前本地版本已提供聊天网页，不直接渲染视频。

## 一、先把项目跑起来

### 1. 在 PyCharm 中打开正确的文件夹

选择「文件 / File → 打开 / Open」，打开：

```text
<项目根目录>
```

左侧项目栏应直接看到 `run.py`、`data`、`src`、`scripts`、`tests` 和 `docs`。这个文件夹就是下文所说的“项目根目录”。

### 2. 选择你已经配好的 Python 环境

在 PyCharm 的「设置 / Settings → Python Interpreter / Python 解释器」中，选择你已有的 **Python 3.10 或以上**环境；也可以在运行配置的解释器下拉框直接选已有环境。具体菜单位置会随 PyCharm 版本略有不同。

这个项目的源码运行只使用 Python 标准库，因此已有环境即使安装了其他包也可以使用，不需要为它重新装一套依赖，也不需要 MySQL、Neo4j 或本地模型。

这里没有指定你电脑上的某个环境名称，因为尚未查看你 PyCharm 中的实际解释器列表；选你已经能正常使用、版本满足要求的环境即可。

### 3. 配置第一次运行

启动路径修复后，根目录 `run.py` 已支持不带任何参数运行：默认离线演示，自动创建结果目录。你当前名为 `python run.py` 的 PyCharm 配置已改为项目根目录和 `$PROJECT_DIR$/run.py`。下表是需要手工建立配置时的参考；参数栏可以留空。

打开顶部「运行 / Run → 编辑配置 / Edit Configurations」，点击「+」，选择 **Python**。如果版本界面不同，也可以先右键根目录的 `run.py` 选择运行，再编辑自动生成的配置。

按下表填写：

| 配置项 | 填写内容 |
|---|---|
| 名称 / Name | 短视频脚本－离线演示 |
| 脚本路径 / Script path | `<项目根目录>\run.py` |
| 脚本参数 / Parameters | 可留空；或显式填写 `--mode mock --output runs/pycharm-mock-01` |
| 工作目录 / Working directory | `<项目根目录>` |
| Python 解释器 / Interpreter | 第 2 步选好的现有环境 |

**参数栏只填 `--mode ...` 这些参数，不要把 `python run.py` 一起填进去。工作目录必须是项目根目录。**

保存配置，在右上角选中「短视频脚本－离线演示」，点击绿色三角形运行。

### 4. 到哪里看结果

底部「运行 / Run」窗口成功时会显示 `status: completed` 和结果路径。默认样例运行后，左侧项目栏会出现：

```text
runs/
└─ pycharm-mock-01/
   ├─ script.md       ← 先打开它，阅读生成的脚本
   ├─ output.json     ← 最终状态和检查结果
   ├─ trace.jsonl     ← 每一步做了什么、工具返回什么
```

如果左侧没有刷新，可对项目目录执行「重新加载 / 从磁盘重新加载」。没有生成草稿时不会有 `script.md`，请先看 `output.json`。

**再次运行前，将参数中的输出目录改成 `runs/pycharm-mock-02`、`runs/pycharm-mock-03` 等新目录。程序不覆盖已有结果。**

Mock 是离线流程模拟，不需要密钥和网络。想看大模型实际创作与修改脚本，请继续下一节。

## 二、在 PyCharm 中运行真实大模型

### 1. 填写模型配置

在左侧项目栏复制 `.env.example`，粘贴到同一目录并命名为 `.env`。如果已经有 `.env`，直接编辑现有文件，不要覆盖已有配置。

打开 `.env`，填写：

```dotenv
VIDEO_API_KEY=替换成你自己的API密钥
VIDEO_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
VIDEO_MODEL=qwen-plus
VIDEO_ENABLE_THINKING=false
```

保存文件。密钥必须有效，不能保留示意文字。文件名称应是 `.env`，不是 `.env.txt`。当前项目只保留配置样例，原客服工程的旧配置已经清理，需要在这里配置新项目使用的密钥。

上述服务地址和模型沿用此前实际验证配置；如果你的账号使用其他服务或地域，请对应修改。真实运行会请求模型服务并产生 API 费用。

### 2. 新建真实运行配置

复制前面的离线运行配置，修改两项：

| 配置项 | 填写内容 |
|---|---|
| 名称 | 短视频脚本－真实模型 |
| 脚本参数 | `--mode real --env-file .env --output runs/pycharm-real-01` |

脚本路径、工作目录和解释器保持前面配置的值。保存，选中此配置，点击绿色运行按钮。

真实调用需要等待，运行窗口可能一段时间没有新输出；默认总运行时间预算为 240 秒，最多 12 次决策。结束后打开 `runs/pycharm-real-01/script.md` 和 `output.json`。

下一次运行将输出目录改成新的编号。模型失败时不会自动改用 Mock。

如果你更习惯使用运行配置里的「环境变量 / Environment variables」，也可以在那里配置 `VIDEO_API_KEY` 等变量，并把参数里的 `--env-file .env` 去掉。两种方式任选一种即可；进程已有的同名环境变量优先于文件里的值。

## 三、我要改主题、受众或时长，修改哪里

打开 `data/request.json`，修改并保存。例如当前输入为：

```json
{
  "theme": "手动字幕和视频裁剪入门",
  "product": "剪映盒演示版",
  "audience": "刚开始剪辑短视频的学生",
  "platform": "抖音",
  "target_seconds": 30,
  "style": "清晰自然，适合口播，不夸张"
}
```

| 字段 | 用途 |
|---|---|
| theme | 主题，必填 |
| audience | 给谁看，必填 |
| platform | 发布平台，必填 |
| target_seconds | 时长上限，必填，写 1–600 的数字，不要写成带引号的字符串 |
| style | 表达风格，必填 |
| product | 可选；限定检索产品，需与素材中的 product 完全一致 |
| instructions | 可选；补充必须包含的内容等要求 |

保存后，再点击「真实模型」运行配置。默认就读取这个文件。目标时长是上限，脚本不一定填满 30 秒。

如果另建 `data/my-request.json`，就在运行配置的参数栏填写：

```text
--mode real --env-file .env --input data/my-request.json --output runs/pycharm-custom-01
```

以上 `run.py` 是单次运行入口。遇到缺信息的追问，请修改 JSON 文件，再用新的输出目录运行。如果希望直接在聊天框补充信息并继续，请改用 `run_chat.py`，见 [聊天页面使用说明](07-chat-guide.md)。

## 四、我要换自己的产品，修改哪里

需求文件中的产品名称和产品资料需要一起修改。只换 `theme` 或 `product`，而不提供资料，程序可能找不到依据。

产品资料在 `data/materials.json`。每项资料是一个对象，数组中可放多项：

```json
[
  {
    "id": "MY01",
    "product": "我的产品",
    "version": "2026-10-29",
    "synthetic": false,
    "keywords": ["字幕", "视频裁剪"],
    "text": "替换成有依据的产品功能、限制和事实。"
  }
]
```

`id` 不可重复；`text` 是事实依据；`keywords` 只帮助检索，不能代替正文。`synthetic` 按资料是否合成如实填写。项目自带产品均为合成示例。

也可以另存为 `data/my-materials.json`，参数改为：

```text
--mode real --env-file .env --input data/my-request.json --materials data/my-materials.json --output runs/pycharm-product-01
```

品牌限制修改 `data/brand_rules.json`；使用其他规则文件时加 `--rules 文件路径`。

## 六、在 PyCharm 中做评测与测试

仍然通过「编辑配置 → + → Python」新建配置。所有配置都选已有解释器，**工作目录统一为项目根目录**。

## 七、怎么看成功或失败

| output.json 中的状态 | 含义 | 你接下来做什么 |
|---|---|---|
| completed | 当前草稿通过自动检查 | 阅读 script.md，并人工核对事实与表达 |
| needs_input | 需要补充输入或资料 | 看 question/missing_fields，改输入后重跑 |
| incomplete | 约束无法满足或步数、时间预算耗尽 | 看 reason、detail、risks 和 Trace，调整需求 |
| failed | 输入或模型服务等发生错误 | 看 reason，排查配置或文件 |

`human_review=pending` 表示还没有独立人工复核，不是程序崩溃。预计时长来自公式，不是已录制配音实测。运行窗口的退出码 0 表示完成，2 表示追问、未完成或失败状态，1 表示命令/文件层面错误。

常见问题：

| 现象 | 先检查什么 |
|---|---|
| 运行按钮不可用、解释器无效 | 是否选中了你已有且有效的 Python 3.10+ 环境 |
| 未填写 --output | 现在会自动在项目 runs 目录创建新目录，不再报缺参数 |
| 找不到 data/request.json | 工作目录是否为项目根目录 |
| FileExistsError | 将 --output 改为新的编号，不覆盖旧结果 |
| missing_api_key | `.env` 是否填写密钥，参数是否包含 --env-file .env |
| http_401 | 密钥是否有效、是否匹配服务地址与账号地域 |
| http_403 / http_404 | 模型访问权限、模型名称及服务地址 |
| http_429 | 账户额度或服务限流 |
| transport_error | 网络、代理或服务地址 |
| JSON 格式错误 | 是否使用英文双引号、正确逗号和数字类型 |
