# 复盘

核心难点是把“程序能跑”与“模型做对了”分开：Mock 可以证明门禁和失败传播，却不能证明查询重写、压缩稿件或正确引用。为此将两种模式分开存档，保留失败与修订记录，并以真实模型补上观察后重新决策的证据。

实现中重点处理了两个容易忽略的问题：修改后旧检查失效，以及重新检查失败时不能保留旧成功结果。另一个取舍是事实检查：原文匹配容易复现但限制创作，模型语义审核允许忠实改写却不保证完全准确，所以两者边界必须写明，并保留独立人工复核入口。

实际发现而非假设的失败包括：多次把 reason 嵌套到 args 导致运行耗尽步数；自动审核漏过了按钮位置等无依据细节。前者用可追踪的有限格式适配修复，后者补充了 R04 证据规则和回归测试，并保留原错误产物。自动验收曾通过但二次阅读发现问题，正说明“状态测试通过”不等于“事实正确”。

原客服框架具备大量可借鉴模块，但三小时建议范围内直接迁移会引入数据库、图检索和接口兼容性等额外工作。独立 CLI 更便于审查业务核心。执行规模和实际耗时由验证产物记录，不能用计划排期代替实际工时。

下一步：用户或外部评审提供隐藏素材与期望；重复关键真实用例评估波动；真人配音校准时长；增加语义审核的反例与冲突资料；验证后再确认 GitHub 仓库并提交最终 SHA。UI、部署、向量库优先级低于这些验证。
